审计要求：

1. 对 rubric 中每个维度恰好输出一条 assessment；确实不适用于当前画面的维度使用 `applicable=false` 和 `score=null`，不能因为证据被裁切、遮挡、虚焦或无法确认而标为不适用。
2. 镜头合同、场景合同和当前生图 prompt 都只是待核对的声明，不是图片已经实现的证据。对每个维度先描述图片中实际可见的人物/建筑比例、空间边界、占位、遮挡或构图关系，再给分；不得从文字声明反推画面合格。
3. 适用维度按 0–10 分评价。每条 assessment 都必须显式输出 `defect` 字段：`score=10` 时写空字符串 `""`；`score<10` 时写一句具体、可观察、可修复的缺陷，绝不能省略或留空。每项都写可观察证据；`major` 或 `critical` 缺陷必须给出至少一个归一化区域 `x1,y1,x2,y2`。
4. 只按加权公式形成总分。不得因为 gate、严重度、单项低分或所谓 hard failure 对总分进行 4.9、5.9、6.9 或任何其他封顶、截断、替换。
5. `approved=true` 仅当未封顶加权总分不低于 {{approval_threshold}}、不存在 `critical` 缺陷，且所有标为 `gate=true` 的适用维度都达到生产协议中的 gate 线。gate 与严重度可以阻止交付，但绝不能修改总分。
6. 只核对人物与建筑的相对比例、人物整体头身比例、空间透视与区域占位、构图层级、遮挡/景别关系、镜头逻辑、世界空间逻辑，以及会污染主视觉的高频颗粒、过度锐化、蜡状/塑料微纹理、重复碎纹、随机亮暗斑、局部脏污和不一致细节频率。人物整体比例可以检查大头娃娃、小躯干或明显短肢，但不得检查手指、脚部细节或步态；不得因为风格像真人电影、不是 3D 国漫、一般材质/色彩/灯光偏好、文字/水印或任何不属于上述范围的问题拒绝。
7. `issues` 只能列出上述允许范围内的可见问题，并写成下一轮提示词可以执行的修复约束。渲染噪点问题必须区分真实材质纹理、合理雾气和合法电影颗粒。若不通过，`revised_prompt` 可以为空字符串；下一轮会把 `issues` 和审计说明交给 `key_vision_prompt` 重新编译完整提示词。若通过则为空字符串。

只输出符合 schema 的 JSON，不要输出 Markdown、解释文字或另一套分数。所有 assessment 必须包含 `defect` 字段；不要遗漏该字段。`weighted_score` 与 `category_scores` 可按你的计算填写，但生产代码会从逐维分数重新计算，最终以代码计算值为准。拒绝原因必须具体、可观察、可修复；不要泛化为“画面质量不足”。
