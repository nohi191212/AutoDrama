# 任务

根据全剧完整正文，维护后续镜头和视频生成会用到的结构化道具资产表 `props`。

这个节点只做道具资产提取与补充，不写生图 prompt，不写画幅、镜头参数、模型名称或图片生成建议。

# 输入

全剧完整正文 novel_full_all_episodes：
{{novel_full_all_episodes}}

已有道具资产 existing_props：
{{existing_props}}

# 输出字段

- `props`：数组。每个元素是一个道具组根，表示同一物件的一组可复用视觉资产。
- `notes`：可选，简短说明本轮新增、保留或调整的依据。

每个 `props[]` 元素必须包含：

- `name`：道具组稳定短名。
- `aliases`：同一物件在正文中的其他称呼，可为空数组。
- `intro`：一句话说明这个道具组的剧情功能、归属或证据价值。
- `episode_keys`：该道具组实际出镜或延续出镜的 episode_key。
- `source_chapters`：可选，源章节或场次。
- `owner_role_name`：如果是明确属于某个角色的随身道具，可填角色名；否则为空或 null。
- `assets`：该道具组下的基准资产和状态变体资产。

每个 `assets[]` 元素必须包含：

- `name`：资产名。基准资产固定使用 `base`；状态变体使用短状态名，如 `激活`、`破损`、`染血`、`烧毁后`。
- `asset_role`：`base` 或 `variant`。
- `status`：状态英文或短键，如 `normal`、`activated`、`damaged`、`bloody`、`burned`。
- `reference_asset_name`：`variant` 通常填 `base`；`base` 填 null 或空字符串。
- `episode_keys`：该具体资产实际出镜或延续出镜的 episode_key。
- `source_chapters`：可选，源章节或场次。
- `desc`：该资产的可见客观描述。
- `visual_features`：基准资产写主体结构、尺寸感、材质、颜色、纹理、识别细节；状态变体可为空或只写仍需锁定的识别点。
- `state_change`：基准资产为空；状态变体只写相比参考资产发生的可见变化。
- `prompt_hint`：给后续出图 prompt 的简短注意事项，可为空。

# 道具提取规则

- 只提取会在故事镜头中实际出现、被角色拿取/摆放/触碰/展示/争夺/破坏/激活，或推动动作、线索、证据、机关判断的关键道具。
- 回忆、照片、视频、屏幕、梦境或幻象中可视化出现，并且会成为镜头识别锚点的关键物件，也可以提取。
- 纯台词提及、纯背景设定、纯关系说明、不会实际可视化出现的物件，不要提取。
- 不要输出泛泛的办公用品、背景陈设、普通家具、普通衣物、纯环境物件、车辆大场景、天气、情绪氛围或没有明确可见物体锚点的概念。
- 不要把固定空间结构、建筑构件或场景组成部分提取为道具，例如石台、祭台、台阶、墙面、地面、门窗、柱梁、房梁、屋檐、桥、道路、假山、池塘、花木、栏杆、雕塑基座等。它们应作为 layout 的 `space_features` 或场景状态处理。
- 固定陈设只有在明确承担可操作机关、独立线索、可移动剧情物或必须单独出图的核心物件时才可作为 prop；仅作为构图中心、承托角色/光效/法术、或烘托空间氛围时不要提取。
- 角色只是短暂触碰环境以确认真实感时，不要把被触碰的花草、墙面、地面、石台等环境细节提取为 prop，除非该物件随后被拿取、破坏、激活或作为线索反复识别。
- 道具组 `name` 使用正文中的稳定短名称，例如「阿林的铁剑」「黑色录音笔」「九尾狐石灯」。不要写项目 ID、文件名、节点名或技术字段。
- 正式名、简称、别称、临时持有人称呼、摆放位置称呼，只要本质是同一物件，都合并到同一个道具组，其他称呼放入 `aliases`。
- 复合称呼如果包含多个可独立出镜并被识别的物件，应拆成多个道具组；如果是不可分割的一套剧情物件，可保留一个组。

# 基准 / 状态资产规则

- 每个道具组必须至少包含一个 `asset_role="base"` 且 `name="base"` 的基准资产。
- `base` 用于锁定同一物件的主体结构、比例、材质关系、颜色基底和核心识别细节。
- `variant` 只表示同一基准道具的关键可见状态变化，例如破损、污染、发光、变形、断裂、烧毁、激活、打开/关闭、血迹/锈迹/泥污变化。
- 主体结构、用途或识别根已经明显变成另一个物件时，不要写成 `variant`，应另起道具组。例如「石灯」和「巨狐爪机关」应是不同道具组。
- 状态变体必须有可判断的参考资产，通常 `reference_asset_name="base"`。
- 状态变体的 `state_change` 只写变化，不重复 base 的完整外观。
- 连续剧情没有明确可见变化时，延续同一个资产；不要因为换场景、换临时持有人、换镜头角度就新建资产。
- 只建实际出镜或明确延续出镜的资产；拿不准是否需要状态图时，宁可不拆。

# 输出要求

- 输出必须是完整 `props`，不是只输出新增项；已有合理道具资产要保留。
- 所有 episode_keys 只允许使用输入正文中真实存在的 episode_key。
- 输出必须符合调用方提供的 JSON schema。
