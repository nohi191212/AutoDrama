# 任务

同时审计已经各自完成终审的道具资产 `props` 和场景资产 `layouts`，解决二者之间的重复、错分和边界冲突。

这个节点只做跨类型边界审核与轻量合并，不读取剧本文本，不写生图 prompt，不输出图片参数，不新增没有依据的剧情资产。

# 输入

已有道具资产 props：
{{props}}

已有场景资产 layouts：
{{layouts}}

# 输出字段

只输出符合 JSON schema 的对象：

- `props`：边界修正后的完整道具资产数组。
- `layouts`：边界修正后的完整场景资产数组。
- `review_notes`：简短说明删除、合并、迁移或保留争议项的原因。

# 核心判断

layout 管“空间组 + 基准空间结构 + 固定环境锚点”。

prop 管“可被单独识别和复用的剧情物件”。它通常可以被角色拿取、携带、摆放、争夺、打开/关闭、破坏、激活，或作为独立机关、证据、线索反复识别。

# 跨类型冲突处理

- 如果某个 prop 本质是固定空间结构、建筑构件或场景组成部分，应从 `props` 删除，并把有价值的外观信息合并进对应 layout 的 `space_features` 或 `brief`。
- 固定空间结构包括但不限于：石台、祭台、台阶、墙面、地面、门窗、柱梁、房梁、屋檐、桥、道路、假山、池塘、花木、栏杆、雕塑基座。
- 如果某个 prop 只是空间构图锚点、承托角色/光效/法术、或营造氛围，不要保留为 prop。
- 如果某个固定陈设明确是可操作机关、独立证据、独立线索，或需要单独出图保持外观一致，可以保留为 prop；同时它也可以作为 layout 的固定特征被提及，但不要在 layout 中拆成独立空间。
- 如果某个 layout 本质只是单个道具、服装、车辆特写、机关部件或纯道具状态，不是可行动空间，应从 `layouts` 删除；若它已对应某个 prop，只保留 prop。
- 如果 prop 和 layout 名称不同但描述的是同一物理对象，要按上述边界保留一方，不要两边都作为独立资产保留。

# 合并与保留规则

- 不要新增剧情里没有依据的新 prop 或 layout。
- 可以把被删除 prop 的客观空间信息合并到最相关的 layout：例如「殿宇石台」删除后，把“中央布满厚灰的石台”写入「古老殿宇」的 `space_features`。
- 合并 layout 信息时保持简短客观，不要写生图 prompt、镜头、画幅、模型或图片生成建议。
- 保留所有合法 episode_keys；不要自造 episode_key，不要输出空 episode_keys。
- 保留 prop 的 base/variant 结构和 layout 的 base/variant 结构；如果删除某个 base，必须同步删除依附它的 variant。
- 如果拿不准，应优先避免重复资产：固定、不可移动、构成空间的对象归 layout；可操作、可携带、可独立触发剧情的对象归 prop。

# 输出要求

- 输出必须是完整 `props` 和完整 `layouts`，不是差异补丁。
- 输出必须符合调用方提供的 JSON schema。
