# 任务

为当前单个角色生成完整角色设计。这个节点按角色递归运行，每次只设计一个角色，并参考全角色索引、剧情提要和已完成角色声音设计，保持角色边界清晰、音色有区分度。

# 输入

当前角色提取结果：
{{role_extract_item}}

全角色索引（用于标准角色名、别名、层级和关系边界；不要把索引当作完整剧情）：
{{role_index}}

全部集/章节的小说剧情提要：
{{role_novel_extract}}

当前角色对应集/章节的完整小说正文（只包含该角色出现的相关集）：
{{role_novel_full}}

已完成角色的声音设计（仅用于保持音色区分度；不要把这里的内容当作剧情事实来源）：
{{designed_role_voices}}

可用音色列表（兼容旧输入；本节点不要从中选择具体 `voice_type`）：
{{available_voices}}

人物设计统一风格要求：{{role_design_style_prompt}}

人物形象图视图要求：{{role_appearance_view_requirement}}

# 总体要求

- 输出的 `roles` 数组只能包含当前角色这一项。
- `name` 必须和“当前角色提取结果”的 `name` 完全一致；不要填写角色 ID 或内部标识。
- 必须继承当前角色提取结果中的 `aliases`、`role_tier`、`has_dialogue`、`visual_reuse_required`、`episode_keys`、`source_chapters`，可以补充但不能删掉已知信息。
- 只依据当前角色对应集/章节的完整小说正文、全部集/章节的小说剧情提要和全角色索引建立身份、关系、外观和道具；已完成角色的声音设计仅作为音色区分参考，不要引入与故事无关的新身份、新关系或新道具。
- `role_tier=primary` 的主要角色要做完整设计：具体身份介绍、性格、人物关系、声音需求、外观设计、和角色强绑定的主要道具。
- `role_tier=functional` 的功能角色要做轻量设计：重点说明短期场景功能、基础外观、必要持物或制服；不要扩写长期人物线、复杂关系网或过重道具系统。
- 功能角色如果 `has_dialogue=false`，`voices` 可以输出空数组；如果 `has_dialogue=true`，至少输出一个 `normal` 基础声音需求条目。
- 全角色索引用于确认其他角色的标准原名和边界；`relationships[].target_role_name` 必须使用索引中的原名，不要使用角色 ID。
- 已完成角色的声音设计只用于避免当前角色声音需求、年龄感、性别感、语速和表演方式重复；不要复制其他角色的 `sample_text` 或身份描述。
- 避免后期关键反转、结局、胜负结果或关键证据剧透；可以描述角色在故事前中期能稳定呈现的身份、气质和功能。
- 输出必须符合调用方提供的 JSON schema。

# 基本设定要求

- `intro` 写给人读，包含年龄感、身份、人物功能和稳定气质，不要写成长剧情梗概。
- `personality` 写 3-6 个性格/行为关键词，逗号分隔即可。
- `relationships` 只写和全角色索引、全部剧情提要或相关正文能支持的关系；`target_role_name` 必须填写对方角色原名；`relation` 写身份关系，`dynamic` 写互动张力，`evidence` 写简短依据。

# 声音设计要求

- 一个角色最终只会由后续 `voice_select` 绑定一个长期复用的官方 `voice_type`。本节点的 `voices` 不是多个候选音色，也不是为不同情绪选择不同人声；它们是同一基础声音在不同 `emotion` 下的声音需求、表演方式和试音文本。
- `role_tier=primary` 的主要角色至少生成一个 `normal` 基础声音需求条目；如果剧情确实需要，可以额外生成 `angry`、`sad`、`happy`、`tense`、`whisper` 或 `other` 情绪表现条目。
- `role_tier=functional` 且 `has_dialogue=false` 的功能角色不要生成声音，`voices` 输出空数组。
- `role_tier=functional` 且 `has_dialogue=true` 的功能角色只生成必要的基础声音需求，通常一个 `normal` 即可，不要扩展多情绪表现条目，除非原文明确需要。
- 不要选择具体 provider 音色，不要填写或编造 `voice_name`、`voice_type`、`voice_resource_id`；这些字段可以为空。最终官方音色由后续 `voice_select` 节点根据全局音色画像和试听样例决定，且同一角色所有情绪会复用同一个官方 `voice_type`。
- `normal.desc` 是后续 `voice_select` 判断角色唯一基础音色的核心依据，必须描述稳定可长期复用的年龄感、性别感、音色、语速、咬字特点和常态表演方式。
- 非 `normal` 的 `desc` 只描述同一基础声音在对应情绪下的表演变化，例如气息、语速、力度、停顿和情绪强度；不要改变角色的年龄感、性别感、声线核心或把它写成另一种人声。
- `sample_text` 使用第一人称，格式为“身份自我介绍 + 可说出口的前期目标/态度”，约 30-45 个中文字符，目标合成音频控制在 10 秒以内；不能涉及后期关键剧情、最终反转、关键证据、结局或胜负结果。
- `sample_text` 必须像角色在试音时直接说出的一段话，不要写内心独白、心理活动、旁白说明或舞台提示；不要包含任何括号类字符，例如 `()`、`（）`、`[]`、`【】`、`{}`、`《》`。

# 外观和道具设计要求

- `appearances` 至少输出一个 `base` 形象。
- `appearances[].role_name` 必须填写当前角色原名。
- `appearances[].desc` 写给人读，包含年龄感、体型、五官、气质、稳定可复用的体貌特征，不写剧情剧透。所描述的应当是常规状态下而受伤、战斗状态下的形象。
- 人物形象设计要克制拟真度：整体画面风格可以保持项目设定的电影级写实CG质感，但人类/类人角色的脸、皮肤、毛发必须偏高质量风格化CG动漫角色，不要写成照片级真人、真实摄影人像、真实皮肤纹理、毛孔、汗渍、微血管、皮肤斑点、真实人脸扫描或可被误判为现实人物肖像的描述。
- 角色识别点优先来自脸型轮廓、眼型、眉形、发型、服装剪裁、配饰、色彩和气质的风格化组合；不要依赖真人级皮肤细节、某个现实明星脸、真实身份证照感或摄影棚人像感。
- `appearances[].role_bound_props` 只列出和该角色强绑定、会影响角色识别或动作方式的主要物品，例如武器、法器、面具、戒指、包、常用工具；不要列全局剧情证物或只出现一次的普通背景物。
- 每个 `role_bound_props` 条目要写清可见特征、真实尺寸感、材质、状态、与角色整体身高或服装位置的比例关系、角色如何佩戴或使用。
- `appearances[].full_body_prompt` 直接用于生成正面全身照参考图。必须写成单人正面全身自然展示，角色从头到脚完整入画，突出稳定脸型、五官、眼神、发型、肤色、年龄感、身高体型、头身比例、基础服装、鞋履、配饰、材质和气质；人物脸部与皮肤必须写成风格化CG/CG动漫质感，不要写照片级真人肖像、真实摄影、真实皮肤毛孔或真实人脸细节；不要立正站立、不要证件照姿势、不要三视图、不要右侧道具设计图、不要其他人物、字幕、水印或文字标识。其中，人类角色在身材比例上，身材一般以8头身为主，特别高大、身材好的用9头身，人物偏矮小的用7头身。
- `appearances[].prompt` 直接用于生成角色三视图 + 道具设计图，并会以 `full_body_prompt` 生成的正面全身照作为参考图。设计图必须是同一张图：左侧或主体区域为同一角色正面、侧面、背面三视图，右侧为其主要绑定物品设计图。右侧道具必须直接以人物三视图为比例参照，和人物保持同一画布比例尺、同一地面基线或同一高度参照线，展示道具本体的真实大小关系、完整轮廓、结构细节和材质，不展示额外手掌、手指、手部持握姿态或其他身体部位。
- `appearances[].prompt` 建议 260-520 个中文字符，必须包含：画面风格要求、人物形象图视图要求、年龄段、性别呈现、地域/时代气质、身高体型、头身比例、脸型、五官、眼神、发型发色、肤色/皮肤质感、常态表情、自然站姿、双臂自然状态、基础服装、鞋履、可复用配饰、材质纹理、干净背景、光线、镜头/构图。
- `appearances[].prompt` 必须明确：三视图人物与右侧主要物品设计图在同一张图中，右侧物品以正交或轻微透视方式单独陈列，并直接对照人物身高、肩宽、腰线或脚边地面基线来体现真实比例；不要用独立刻度尺作为主要比例参照，不要用手掌、手指、手臂、持握姿态或真实身体部位作为比例参照；无其他人物、无字幕、无水印、无文字标识、无多余肢体、不要夸张畸变。
- `appearances[].prompt` 必须使用更温和的角色设定图表达。即使原文有战斗、死亡、尸化、伤口、血迹、恐怖变异等信息，也要改写成低风险视觉元素：病态苍白、疲惫眼神、异化纹理、服装破损、尘土、泥污、旧污渍、暗色裂纹、非写实纹样。不要写血液、血渍、开放性伤口、内脏、断肢、写实尸体或 gore 细节；衣服上的血迹统一替换为泥土、脏污或旧污渍。
- 右侧物品比例参照必须直接使用左侧人物：例如“道具与左侧人物保持同一比例尺”“道具底部与左侧人物脚边地面线对齐”“道具高度约为左侧人物身高的三分之一”。不要写“手掌长度”“手持比例”“简化手掌轮廓”“人物持握姿态”“放置一只真实手掌”等任何手部参照，也不要把刻度尺作为主要参照。
- 对真人电影质感或爱死机写实CG风，也只保持镜头、光影、场景、材质的电影质感；人物脸部和皮肤仍必须是风格化CG/CG动漫角色，不要写真实摄影、真实皮肤纹理、毛孔汗渍、真实人脸扫描或照片级真人肖像；对 `appearances[].prompt` 仍要输出三视图 + 道具设计图。
- 对 2D/3D/CG 风格角色，要严格保留对应风格，不要混入真人摄影词；`appearances[].prompt` 必须明确正面、左面、背面并排，同一身高比例和同一服装细节。
- 角色识别点必须来自稳定体貌、气质、发型、服装剪裁、配饰和色彩关系；不要把某一件临时剧情道具、伤痕、血迹、雨水、表情崩溃当作 base 形象的唯一识别点。
- `role_tier=primary` 时，`intro_video_prompt` 用于后续以设计图为参考生成 4 秒角色介绍视频。风格向 Seedance 官方示例靠拢：写成一段连续自然语言，引用参考素材时使用“参考图片1”或“图片1中的人物外观”，再用 `0-1.5 秒：...；1.5-3 秒：...；3-4 秒：...。` 这样的内嵌时间段描述动作和镜头，时间段必须只覆盖 0-4 秒，不要写成分镜数组、分条清单或方括号标签。
- `role_tier=primary` 时，`intro_video_prompt` 必须描述：人物站在洁净、亮度适中的虚空圆台上，圆台缓慢转动；人物做几个符合身份和性格的常见动作；如有绑定物品，要展示佩戴、握持或使用方式；视频整体符合人物常见场景气质，但背景仍保持干净抽象，不出现剧情剧透。
- `role_tier=functional` 时，`intro_video_prompt` 可以为空；功能角色默认不生成介绍视频。
- `intro_video_prompt` 不要出现字幕、水印、文字标识或其他人物；如需声音，只写自然环境声或衣料、道具轻响，不要额外编写对白。
