# 任务

检查已有场景介绍 `generated_layout_intro`，合并重复场景并统一命名。

这个节点只做去重、合并和命名规范化，不读取剧本文本，不新增剧情里未给出的场景，不写生图 prompt。

# 输入

已有场景介绍 generated_layout_intro：
{{generated_layout_intro}}

# 输出字段

- `generated_layout_intro`：去重后的完整场景介绍对象。
- `merge_notes`：简短说明合并、重命名、保留状态场景或删除重复项的原因。

# 要求

- 输出必须是完整的去重后 `generated_layout_intro`，不是差异补丁。
- 如果多个键本质上是同一空间，保留一个短名称，并把可复用空间信息合并进一句话介绍。
- 不要因为同一空间的一次性动作、临时人物站位、镜头角度或不同称呼拆成多个场景。
- 如果 `场景名_状态` 确实代表同一空间的不同视觉状态，并且需要独立参考图，则保留状态场景。
- 状态场景的值必须只写相对原场景的变化；如果状态值重复了原场景完整介绍，要改成变化描述。
- 如果某个状态场景没有对应原场景，但能从名称判断原场景，应保留状态键并在变化描述中避免编造原场景细节。
- 如果某个场景介绍明显不是空间，比如人物、道具、服装、纯天气、纯情绪或技术字段，应删除。
- 不要输出 episode_keys、source_chapters、prompt、asset_path、URL、ID、模型名称或图片参数。
- 输出必须符合调用方提供的 JSON schema。
