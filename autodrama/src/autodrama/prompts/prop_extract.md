# 任务

根据全剧完整正文，维护后续长剧集镜头生成会用到的道具介绍表 `generated_prop_intro`。

这个节点只做道具提取与补充，不写生图 prompt，不写画幅、镜头参数、模型名称或图片生成建议。

# 输入

全剧完整正文 novel_full_all_episodes：
{{novel_full_all_episodes}}

已有道具介绍 generated_prop_intro：
{{generated_prop_intro}}

# 输出字段

- `generated_prop_intro`：对象，键为道具名，值为一句话介绍。
- `notes`：可选，简短说明本轮新增、保留或调整的依据。

# 要求

- 输出必须是完整的 `generated_prop_intro`，不是只输出新增项；已有合理道具要保留。
- 道具提取服务于后续镜头和视频生成参考图。只有会在故事镜头中实际出现、被角色拿取/摆放/触碰/展示/争夺/破坏/激活、推动动作或情节判断的道具才需要提取。
- 如果一个道具只是被台词、旁白、背景设定或回忆一带而过提及，但故事镜头没有实际展示它，不要提取。
- 不要输出泛泛的办公用品、背景陈设、普通家具、普通衣物、纯环境物件或没有剧情功能的装饰物。
- 道具名使用剧本文字中的稳定短名称，例如「阿林的铁剑」「黑色录音笔」「九尾狐石灯」。不要写项目 ID、文件名、节点名或技术字段。
- 道具一句话介绍只写它的可见稳定特征、剧情功能、归属或证据价值，说明它为什么需要成为镜头参考图；不要写完整生图 prompt。
- 如果同一种道具有不同关键可见状态，并且状态变化会影响后续镜头参考图，应使用 `道具名_状态` 作为键，例如「阿林的铁剑_破损」「合同_烧毁后」「九尾狐石灯_激活」。
- 状态道具的值只写“相比原道具发生了哪些变化”，例如破损、污染、发光、变形、断裂、烧毁、激活后的能量纹路、血迹/锈迹/泥污变化；不要重复原道具完整介绍。
- 如果某个状态道具没有对应原道具，但能从名称判断原道具，应保留状态键并避免编造原道具细节。
- 不要输出角色、场景、服装、车辆大场景、纯天气、纯情绪氛围或没有明确可见物体锚点的概念。
- 输出必须符合调用方提供的 JSON schema。
