# 任务

从用户提供的原始剧本文本中，提取后续短剧生成流程需要的结构化信息。

这是导入抽取任务，不是改写任务。你只需要理解原文已经写明的内容，并整理为结构化 JSON。

# 输入

原始剧本文本：
{{raw_script}}

# 输出 JSON 格式

请输出严格 JSON，字段如下：

```json
{
  "outline": "整体剧情概要",
  "episode_outlines": ["第一集剧情概要", "第二集剧情概要"],
  "roles": [
    {
      "name": "角色名",
      "role_tier": "primary",
      "intro": "一句话说明身份、剧情功能和稳定识别信息",
      "aliases": ["别称或称谓"],
      "appearance_notes": ["原文明确给出的稳定外观线索"],
      "has_dialogue": true,
      "visual_reuse_required": true,
      "evidence": "不超过80字，说明原文依据"
    }
  ],
  "props": [
    {
      "name": "道具名",
      "desc": "一句话说明可见特征、归属、剧情功能或证据价值",
      "status": "normal",
      "owner_role_name": "角色名或空字符串",
      "evidence": "不超过80字，说明原文依据"
    }
  ],
  "layouts": [
    {
      "name": "场景名",
      "desc": "一句话说明空间功能和可见稳定特征",
      "prompt": "用于后续场景图生成的简短视觉描述，只基于原文明确线索",
      "evidence": "不超过80字，说明原文依据"
    }
  ],
  "notes": "简短说明抽取判断；如果原文没有明确提供角色、道具或场景，也说明为空的原因"
}
```

# 总体要求

- 只依据原始剧本文本抽取，不要使用常识补全缺失信息。
- 不要创造原文没有的人物、道具、场景。
- 不要改写剧情，不要扩写剧情，不要补拍摄细节。
- 不要输出完整剧本文本。
- 不要输出 Markdown 代码块，不要输出解释文字，只输出 JSON。
- 如果某类信息原文没有明确提供，输出空数组，例如 `"props": []`。
- 字段值不要写项目 ID、文件名、节点名、模型名或技术字段。
- 输出必须符合调用方提供的 JSON Schema。

# outline 要求

- `outline` 写整体剧情概要，控制在 300-800 字。
- 必须包含主要人物、核心冲突、关键目标、主要转折、结尾状态。
- 不要写成宣传文案，不要写成分镜，不要写旁白。

# episode_outlines 要求

- `episode_outlines` 写多集剧情概要列表，每个列表项对应一集。
- 每个列表项必须覆盖该集的主要事件、人物行动、冲突推进和结尾悬念或状态。
- 如果输入文本本身就是单集成熟剧本，`episode_outlines` 只输出一个列表项。
- 如果输入文本包含多集、章节或明显阶段，可以按剧情结构拆成多个列表项；不要在文本中自造 episode_key、文件名或技术编号。

# roles 抽取要求

- 只提取会被看见、听见、明确行动、明确说话、明确影响剧情的人物。
- 如果原文在角色表、人物表、开场说明中提供了角色，也可以提取。
- 如果角色只在背景设定中一带而过，且没有进入当前剧情，不要提取。
- `name` 必须使用原文中的稳定名称。
- `role_tier` 只能是 `primary` 或 `functional`。
- `primary`：主角、反派、核心盟友、核心亲属、情感对象、师长、长期影响主线的人。
- `functional`：短期承担信息传递、阻碍、引导、战斗、救治、通报、盘问、服务等场景功能的人。
- 群体不要作为角色输出，例如“众人”“弟子们”“妖兵们”。如果群体中有独立行动者，拆成具体人物或稳定身份称谓。
- `intro` 写一句话，包含身份、剧情功能、可识别信息。
- `aliases` 只写原文出现的别称、称谓、身份称呼，不要自造。
- `appearance_notes` 只写原文明确给出的外观线索；没有就填空数组。
- `has_dialogue` 表示是否有明确对白、喊话、传音、命令或可听见发言。
- `visual_reuse_required` 表示后续镜头是否需要保持稳定视觉形象；主要角色通常为 true，功能角色按剧情需要判断。
- `evidence` 写原文依据摘要，不要超过 80 字。

# props 抽取要求

- 只提取后续镜头中需要实际看见、拿取、展示、争夺、破坏、激活、证明身份或推动剧情的道具。
- 不要提取普通背景陈设、普通家具、普通衣物、泛泛办公用品、纯环境物。
- 如果一个物件只是台词提到，但没有实际展示或剧情功能，不要提取。
- `name` 使用原文中的稳定短名称。
- `desc` 写一句话，说明可见特征、归属、剧情功能或证据价值。
- `status` 默认 `normal`。如果原文明确有关键状态，可以写短状态，例如 `broken`、`activated`、`burned`、`bloodstained`。
- `owner_role_name` 只在原文明确归属某角色时填写，否则填空字符串。
- `evidence` 写原文依据摘要，不要超过 80 字。

# layouts 抽取要求

- 只提取剧情真实发生、角色行动、对话、对峙、追逐、探索、仪式、战斗、关键事件所在的空间。
- 如果地点只是背景设定或台词提到，但当前剧情没有发生在那里，不要提取。
- 合并本质相同的地点，不要因为镜头角度、临时动作、短暂道具摆放拆成多个场景。
- `name` 使用短场景名，例如“小燕家大厅”“医院走廊”“后山祭坛”。
- `desc` 写一句话，说明空间功能和可见稳定特征。
- `prompt` 写简短视觉描述，只基于原文明确线索；不要写镜头参数、画幅、模型名、生图指令。
- 如果原文没有视觉线索，`prompt` 可以等于 `desc`，但不要脑补风格。
- `evidence` 写原文依据摘要，不要超过 80 字。

# 自检

输出前请检查：

- JSON 可以被直接解析。
- 不包含 Markdown 代码块。
- 没有编造原文不存在的人物、道具、场景。
- 没有输出完整剧本文本。
- 没有输出多余字段。
