# 任务

为指定集自回归生成电影级视频片段规划。当前调用只生成一个 `shot`，不要一次性输出整集 `shots` 数组。

输出会被调用方逐个累积，最终写入 shots 目录。你必须根据已经生成的片段继续向后规划，避免重复覆盖同一段剧情。

# 输入

标题：{{title}}

集键名：{{episode_key}}

本集剧情依据：
{{episode_story}}

前序分镜历史（前序视频片段历史）：
{{previous_storyboard_history}}

本集已生成 shot：
{{generated_shots}}

当前要生成的 shot index：{{shot_index}}

本集最少 shot 数：{{min_shots}}

本集最多 shot 数：{{max_shots}}

本集已规划时长：{{current_duration_seconds}} 秒

本集参数目标时长：{{target_duration_seconds}} 秒

角色资产：
{{roles}}

道具资产：
{{props}}

场景资产：
{{layouts}}

画面风格：{{visual_style_label}}

画面风格要求：{{visual_style_prompt}}

# 输出格式

只输出符合调用方 JSON schema 的 JSON，不要 Markdown，不要解释。顶层字段为：

- `episode_key`：必须等于输入的集键名。
- `shot`：当前这一次生成的单个视频片段规划。
- `is_episode_complete`：本 shot 生成后，本集是否已经覆盖完整最终剧本。
- `completion_reason`：一句话说明为什么继续或为什么结束。

当前调用只生成 `shot.index = {{shot_index}}` 的一个片段。不要输出其他 index，不要输出 `shots` 数组。

# 完成判断

- 如果 `{{shot_index}}` 小于 `{{min_shots}}`，`is_episode_complete` 必须为 `false`。
- 如果本 shot 之后仍有关键剧情、关键动作、关键情绪转折、关键视觉状态未覆盖，`is_episode_complete` 必须为 `false`。
- 如果本 shot 已经覆盖本集剧情依据的结尾，并且总 shot 数不少于 `{{min_shots}}`，`is_episode_complete` 可以为 `true`。
- 如果已经到 `{{max_shots}}`，必须在当前 shot 内收束本集剩余内容，并把 `is_episode_complete` 设为 `true`。
- 总规划时长应接近本集参数目标时长，但不要在 `video_prompt` 里写“目标时长”这类调度信息。

# shot 必填字段

`shot` 必须包含：

- `shot_id`：使用 `{episode_key}_shot_001` 这类稳定 ID。
- `index`：必须等于当前 `{{shot_index}}`。
- `layout_id`：必须引用已有场景资产 ID。
- `title`：短标题，给人类审阅和日志使用。
- `duration_seconds`：4.0-15.0 秒，优先使用整数秒。
- `transition`：硬切、匹配剪辑、闪白、溶解、结尾停在可硬切状态等。
- `start_frame_source`：`new_reference_frame` 或 `previous_shot_last_frame`。
- `start_frame_inheritance_reason`：20-80 个中文字符，说明为什么继承或为什么重新建立画面。
- `role_ids`、`role_appearance_ids`、`role_audio_ids`、`prop_ids`：只要角色、外观、音色或道具在本片段任意时刻出现，就必须引用已有 ID。
- `dialogue`：只写本片段需要合成语音和字幕的对白；没有对白则为空数组。
- `ref_frame_prompt`：完整单帧参考帧主体 prompt。
- `video_prompt`：完整连续视频片段主体 prompt。

旧的结构化视觉字段 `content`、`scene_description`、`composition`、`lighting`、`sound_design`、`camera_shooting_angle`、`camera_movement`、`focal_length` 只作为兼容旧数据的可选字段；新输出不要依赖它们补充画面信息，能省略就省略。所有场景、构图、光线、机位、焦段、动作、节奏、声音和结尾状态都要自然融合进 `ref_frame_prompt` 或 `video_prompt`。

# 剧情拆分要求

- 先阅读本集剧情依据，再结合“本集已生成 shot”判断已经覆盖到哪里。
- 当前 shot 必须从尚未覆盖的剧情继续向后推进，不要重复已经生成的动作，除非剧本明确要求回放、闪回或呼应。
- 一个 shot 可以覆盖剧本中的一个强视觉动作、一段明确情绪推进、一次空间建立、一次冲突揭示或一次转场。
- 不要把大量剧情压缩成摘要。片段规划是给生图和视频模型执行的，不是给人看梗概。
- 需要让不同执行者读完 `video_prompt` 后能想象出高度一致的画面、运镜、动作和声音。

# ref_frame_prompt 要求

`ref_frame_prompt` 用于参考帧生图，是单帧画面主体 prompt。复杂关键镜头建议 500-1000 个中文字符，简单过渡镜头也要足够具体。必须写“这一帧是什么”，不要写动作过程。

必须自然包含：

- 画面风格关键词。
- 场景、时间、天气或空间状态。
- 首帧可见的人物、人物站位、姿态、视线、稳定外观特征。
- 首帧可见的关键道具、道具位置、材质和可识别细节。
- 景别、机位、镜头方向、焦段或镜头类型。
- 前景/中景/背景层次、负空间、主体边缘位置。
- 主光、辅光、轮廓光、反射、阴影、色温和色彩关系。
- 材质纹理、环境粒子或静态环境状态。
- 9:16 竖屏短剧构图。
- 禁止字幕、水印、文字标识、片段编号和无关人物。

参考帧是本片段首帧视觉基准，不是本片段全部内容的资产清单。若本片段中的角色或道具会在后续运镜中出现，但首帧是纯环境建立镜头，可以在 `role_ids` / `prop_ids` 中引用它们，并在 `video_prompt` 里写清它们何时、如何进入画面；不要为了资产锚点强行把首帧改成人物站桩图。

# video_prompt 要求

`video_prompt` 用于视频生成，是连续视频片段主体 prompt。复杂关键镜头建议 900-1800 个中文字符，简单过渡镜头建议 600-1000 个中文字符。必须写“从起始画面开始，接下来几秒发生什么”，不要只写剧情摘要。

`video_prompt` 必须按片段内部时间段书写。每个时间段用 `[起始秒~结束秒秒]` 或 `[起始秒-结束秒秒]` 开头，结束处必须标明切镜或声音衔接提示，例如 `[硬切]`、`[J-Cut]`、`[L-Cut]`、`[匹配剪辑]`、`[溶解]`、`[无切]`。示例格式：`[0~4.0秒] xxxx4秒钟的镜头内容xxxx [硬切]。[4.0-7.5秒] xxxx3.5秒钟的镜头内容xxxx [J-Cut]。` 时间段必须覆盖完整 `duration_seconds`，相邻段首尾时间必须连续，不要互相重叠或留下空档。

必须自然融合：

- 起始画面与首帧状态，不要用模板化开头如“生成一个连续视频片段”。
- 镜头从哪里开始：空间位置、高度、距离、朝向、俯仰角、镜头焦段或镜头感。
- 镜头如何运动：推、拉、横移、环绕、升降、俯冲、悬停、手持、稳定器、速度曲线、停顿点和终止构图。
- 光照：光源方向、软硬、色温、明暗比、体积光、反射、高光、阴影移动和光线变化。
- 色彩与材质：主色调、冷暖对比、饱和度、材质反光、皮肤/布料/金属/石材/雾气等真实质感。
- 角色动作：身体重心、手部动作、视线变化、呼吸、喉结、微表情、衣物受力、脚步和姿态变化。
- 道具变化：接触方式、位置变化、能量状态、发光、破损、血迹、反射或证据呈现方式。
- 环境动态：雾、云、雨、雪、灰尘、火焰、粒子、屏幕频闪、空间扭曲、风压等如何持续变化。
- 声音设计：环境底噪、低频、风声、金属声、衣料声、脚步声、能量声、混响、延时、静默和对白声音质感。
- 节奏：停顿、加速、压低、爆发、凝滞、呼吸感和情绪推进。
- 结尾状态和转场准备：结尾停在哪个构图、哪个动作或哪个可匹配状态。

允许在单个 shot 内出现少量明确剪辑。如果需要切镜头，必须在对应时间段末尾写明 `[硬切]`、`[J-Cut]`、`[L-Cut]`、`[匹配剪辑]` 或其他明确衔接方式，并说明切换后的景别、机位、主体、动作、光线和声音如何延续。不要写模糊的“多机位快速剪辑”或“画面切换若干细节”；每一次切换都必须让人知道具体画面是什么。

`video_prompt` 不要包含调度标签，例如“剧集：”“目标时长：”“片段编号：”。可以自然写时长感和节奏，但不要把系统参数原样塞进 prompt。

# 镜头继承关系

每个 shot 必须选择 `start_frame_source`：

- 第一镜默认 `new_reference_frame`。
- 后续片段如果与上一片段在同一时空、同一动作连续、需要保持人物姿态/能量位置/镜头方向连续，则可选 `previous_shot_last_frame`。
- 如果发生时间跳跃、地点变化、视角大幅改变、闪回、插入画面或需要重新建立空间，则选 `new_reference_frame`。
- `start_frame_inheritance_reason` 必须说明为什么继承或为什么不继承，20-80 个中文字符。
- 选择 `previous_shot_last_frame` 时，`video_prompt` 必须明确本片段如何从上一片段末尾状态开始，而不是重新摆拍。
- 选择 `previous_shot_last_frame` 会让视频生成阶段把上一片段尾帧作为本片段严格首帧使用；不要为了普通风格一致性滥用，只在动作、姿态、能量特效或空间方位必须无缝延续时使用。

# 基本约束

- `episode_key` 必须等于输入的集键名。
- `shot.index` 必须等于当前 `{{shot_index}}`。
- `shot.shot_id` 必须符合 `{episode_key}_shot_001` 递增格式。
- 生成当前集视频片段规划时必须参考前序分镜历史，保持角色行动、场景位置、道具状态和片段节奏连续。
- 不要重复前序集已经完成的关键动作，除非本集剧本明确要求回放、复现或呼应。
- 如需延续前序集的场景、角色或道具，必须使用已有 ID。
- 每个 shot 必须引用已有 `layout_id`，如出现角色或道具，也必须引用已有 ID。
- 不要引用不存在的角色、道具、外观、音色或场景。
- 不要输出不属于当前 schema 的额外字段。
