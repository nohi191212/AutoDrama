# 任务

为指定集生成电影级视频片段规划 JSON。片段规划会写入 slots 目录，不写入 state.json。

# 输入

标题：{{title}}

集键名：{{episode_key}}

本集最终剧本：
{{episode_script}}

前序分镜历史（前序视频片段历史）：
{{previous_storyboard_history}}

角色资产：
{{roles}}

道具资产：
{{props}}

场景资产：
{{layouts}}

画面风格：{{visual_style_label}}

画面风格要求：{{visual_style_prompt}}

# 输出目标

为当前集生成 3-9 个连续视频片段 shot。每个 shot 都要让参考帧生图模型和视频生成模型可以直接执行，不要把画面信息拆散到多个视觉字段里。

每个 shot 只维护两个核心生成提示词：

- `ref_frame_prompt`：完整单帧参考帧主体 prompt。
- `video_prompt`：完整连续视频片段主体 prompt。

旧的结构化视觉字段 `content`、`scene_description`、`composition`、`lighting`、`sound_design`、`camera_shooting_angle`、`camera_movement`、`focal_length` 只作为兼容旧数据的可选字段；新输出不要依赖它们补充画面信息，能省略就省略。所有场景、构图、光线、机位、焦段、动作、节奏和结尾状态都要自然融合进 `ref_frame_prompt` 或 `video_prompt`。

# 必填字段

每个 shot 必须包含：

- `shot_id`：使用 `{episode_key}_shot_001` 这类稳定 ID。
- `index`：从 1 递增。
- `layout_id`：必须引用已有场景资产 ID。
- `title`：短标题，给人类审阅和日志使用。
- `duration_seconds`：4.0-15.0 秒，优先使用整数秒以适配 Seedance 2.0。
- `transition`：硬切、匹配剪辑、闪白、溶解等；也可写“结尾停在可硬切状态”。
- `start_frame_source`：`new_reference_frame` 或 `previous_shot_last_frame`。
- `start_frame_inheritance_reason`：20-80 个中文字符，说明为什么继承或为什么重新建立画面。
- `role_ids`、`role_appearance_ids`、`role_audio_ids`、`prop_ids`：如出现角色、外观、音色或道具，必须引用已有 ID。
- `dialogue`：只写本片段需要合成语音和字幕的对白。
- `ref_frame_prompt`：完整单帧参考帧主体 prompt。
- `video_prompt`：完整连续视频片段主体 prompt。

# `ref_frame_prompt` 要求

`ref_frame_prompt` 用于参考帧生图，是单帧画面主体 prompt，建议 180-360 个中文字符。必须写“这一帧是什么”，不要写动作过程。

必须自然包含：

- 画面风格关键词。
- 场景、时间、天气或空间状态。
- 出场人物、人物站位、姿态、视线、稳定外观特征。
- 关键道具、道具位置、材质和可识别细节。
- 景别、机位、镜头方向、焦段或镜头类型。
- 前景/中景/背景层次、负空间、主体边缘位置。
- 主光、辅光、轮廓光、反射、阴影和色温。
- 材质纹理、环境粒子或静态环境状态。
- 9:16 竖屏短剧构图。
- 禁止字幕、水印、文字标识、片段编号和无关人物。

# `video_prompt` 要求

`video_prompt` 用于视频生成，是连续视频片段主体 prompt，建议 260-520 个中文字符。必须写“从起始画面开始，接下来几秒发生什么”，不要只写剧情摘要。

必须自然融合：

- 起始画面与首帧状态。
- 3-8 秒内的动作推进，不要写成多镜头混剪脚本。
- 角色动作、手部动作、身体重心、视线变化、呼吸、微表情。
- 道具变化、接触方式、能量状态或证据呈现方式。
- 环境粒子、雨、雾、灰尘、反光、屏幕频闪等如何持续变化。
- 机位、运镜速度、焦段、构图变化、景别变化。
- 光线变化、遮挡、反射和阴影运动。
- 片段节奏：停顿、加速、压低、爆发、凝滞等。
- 结尾停留状态和转场准备，例如“结尾停在可硬切状态”“为下一片段留下匹配动作”。

`video_prompt` 控制的是单个连续视频片段内部的动作节奏，不是真正的剪辑时间线。如需要剪辑感，用“开头快速进入动作”“结尾停在可硬切状态”“保留匹配动作给下一片段”等说法，不要写“切到另一个镜头”“多机位快速剪辑”。

注意：`ref_frame_prompt` 和 `video_prompt` 是片段级主体提示词，不是最终发送给图像或视频模型的完整请求日志。后续代码会在实际生成前轻量注入画面风格、参考资产、一致性要求、输出规格、首帧继承关系和禁止项。但不要依赖旧的 slot 视觉字段补充画面；核心画面与动作必须已经写在这两个 prompt 中。

# 镜头继承关系

每个 shot 必须选择 `start_frame_source`：

- 第一镜默认 `new_reference_frame`。
- 后续片段如果与上一片段在同一时空、同一动作连续、需要保持人物姿态/能量位置/镜头方向连续，则可选 `previous_shot_last_frame`。
- 如果发生时间跳跃、地点变化、视角大幅改变、闪回、插入画面或需要重新建立空间，则选 `new_reference_frame`。
- `start_frame_inheritance_reason` 必须说明为什么继承或为什么不继承，20-80 个中文字符。
- 选择 `previous_shot_last_frame` 时，`video_prompt` 必须明确本片段如何从上一片段末尾状态开始，而不是重新摆拍。
- 选择 `previous_shot_last_frame` 会让视频生成阶段把上一片段尾帧作为本片段严格首帧使用；不要为了普通风格一致性滥用，只在动作、姿态、能量特效或空间方位必须无缝延续时使用。

# 基本约束

- `episode_key` 必须等于输入的集键名。
- 生成本集视频片段规划时必须参考前序分镜历史（前序视频片段历史），保持角色行动、场景位置、道具状态和片段节奏连续。
- 不要重复前序集已经完成的关键动作，除非本集剧本明确要求回放、复现或呼应。
- 如需延续前序集的场景、角色或道具，必须使用已有 ID。
- 本集片段规划只输出当前 `episode_key`，不要输出前序集片段。
- 生成 3-9 个视频片段，按 `index` 从 1 递增。
- 每个 shot 必须引用已有 `layout_id`，如出现角色或道具，也必须引用已有 ID。
- `duration_seconds` 合计应接近本集目标时长；单个片段通常 4.0-8.0 秒，动作复杂片段可更长，但不要超过 15.0 秒。
- 不要引用不存在的角色、道具或场景。
- 输出必须符合调用方提供的 JSON schema。
