# 任务

检查已有结构化道具资产 `props`，合并重复道具组，规范基准资产与状态变体资产。

这个节点只做去重、合并、命名规范化和资产层级校正，不读取剧本文本，不新增剧情里没有依据的道具，不写生图 prompt。

# 输入

已有道具资产 props：
{{props}}

# 输出字段

- `props`：去重后的完整道具资产数组。
- `merge_notes`：简短说明合并、重命名、保留状态资产、补充 base 或删除重复项的原因。

# 去重与合并规则

- 输出必须是完整去重后的 `props`，不是差异补丁。
- 如果多个道具组本质是同一个物件，保留一个稳定短名，把其他称呼放入 `aliases`，并合并可复用外观、功能、归属或证据信息。
- 不要因为同一物件的一次性摆放位置、临时手持者、镜头角度、称呼差异、轻微描述差异拆成多个道具组。
- 如果复合道具名实际包含多个独立可见物件，应拆为多个道具组；如果是一套不可分割的剧情物件，可保留为一个组。
- 如果某个条目明显不是道具，比如人物、场景、服装、普通背景家具、纯天气、纯情绪或技术字段，应删除。

# 基准 / 状态资产审核规则

- 每个道具组必须至少保留一个 `asset_role="base"`、`name="base"` 的基准资产。
- 如果状态资产没有 base，但能从道具组信息稳妥补出 base，应补充 base；如果不能稳妥判断，应把该资产改为 base 或拆成独立道具组，不要编造复杂细节。
- 如果一个 `variant` 实际是另一个物件，而不是同一物件的状态变化，应拆成新的道具组。
- 如果多个 `variant` 只是同一轻微状态的重复说法，应合并成一个短状态名。
- `variant.state_change` 必须只写相比 `reference_asset_name` 的变化；如果重复了 base 的完整描述，要改成变化描述。
- `variant.reference_asset_name` 必须指向同一道具组内的 base 资产，通常是 `base`。
- 连续场次没有明确变化时，延续同一个资产，不因换场景、换持有人、换镜头拆分。

# 字段要求

- 不要输出 prompt、asset_path、URL、ID、模型名称或图片参数。
- `episode_keys` 只保留输入中已有的合法键，不要自造。
- `desc`、`visual_features`、`state_change` 要客观可画，不写情绪、氛围或心理判断。
- 输出必须符合调用方提供的 JSON schema。
