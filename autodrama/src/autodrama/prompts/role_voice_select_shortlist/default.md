# 任务

根据角色资料、角色身份板参考和已经过滤后的候选音色画像，从候选音色中筛选最适合作为该角色长期统一基础音色的 top 3。

# 输入

角色设定：
{{role_profile}}

候选音色画像：
{{voice_profiles}}

# 要求

- 只基于角色声音需求、身份、年龄感、性别呈现、性格和短剧对白自然度进行筛选。
- 如果角色设定包含 `visual_reference_assets`，必须把人物图呈现的视觉年龄、体态、脸部气质、服装风格和整体能量纳入判断，避免声线和形象明显脱节。
- 输入中的候选音色已经由程序过滤为中文、角色同性别、目标 TTS 模型候选；不要选择输入列表之外的任何音色。
- 一个角色最终只会绑定一个官方 `voice_type`，后续所有情绪和对白都会复用这个音色；不要为不同 `emotion` 分别选择不同音色。
- 角色设定中的 `audio[].emotion` 表示同一基础音色下的情绪表演参考，不是多个独立音色候选。优先以 `normal` 的 `desc` 和 `sample_text` 判断基础音色，其他情绪只用于判断候选音色的稳定性、表现范围和是否会在强情绪下失真。
- 不要因为某个单一情绪样例特别夸张或贴合，就选择一个偏离角色常态年龄感、性别呈现或身份气质的音色。
- 每个候选都有内部 `candidate_id`（例如 `V001`）。输出时必须逐字复制被选候选的 `candidate_id`、`voice_label` 和 `voice_type`，不要翻译、缩写或自造。
- `candidate_id` 是本轮选择的锁定编号；如果 `candidate_id` 和 `voice_type` 无法对应，优先保持输入中的同一条候选。
- 使用 `voice_label` 给人读，使用 `voice_type` 作为唯一 provider 标识。
- 最多输出 3 个候选，按适配度从高到低排序。
- 每个候选的 `voice_type` 必须逐字复制候选音色画像中的值。
- 警惕过强广告腔、客服腔、播音腔、动漫腔。
- 如果官方描述和画像冲突，优先相信画像。
- 输出必须符合调用方提供的 JSON schema。
