# 任务

从全本完整小说中提取所有应进入角色资产链的角色，并记录每个角色出现在哪些集和源章节中。

注意：当前推荐流程已经拆分为 `role_extract_primary` 和 `role_extract_functional`。此模板仅作为兼容入口使用，仍然必须按 `role_tier=primary/functional` 输出，不要使用旧的五级 `importance`。

标题：{{title}}

原始故事：
{{raw_script}}

完整小说正文（按集组织，每集可能包含“源章节：第X章-第Y章”等信息）：
{{novel_full}}

已提取角色列表（每项是 `[角色名, 一句话识别说明]`，用于辨认同名/同称谓角色并避免重复输出）：
{{existing_roles}}

全集 episode_key 列表：{{episode_keys}}

# 要求

- 提取所有会在剧情中被看见、听见或明确参与事件且需要进入角色资产链的角色，包括主要角色和功能角色。
- 本轮只输出“已提取角色列表”中尚未包含的新增角色；不要重复输出已提取角色。
- 如果全本完整小说中已经没有新增角色，输出空的 `roles` 数组。
- 先判断 `primary`，再判断 `functional`，最后把纯背景存在排除在 `roles` 之外。
- `role_tier` 只能为 `primary` 或 `functional`。
- `primary`：主角、反派、核心盟友/亲属/师长/情感对象，或对主线、关系、阵营冲突、长期剧情有持续影响的人。
- `functional`：不承担长期人物线，但有独立动作、对白、交互、信息传递、阻碍、引导、战斗、救治等短期场景功能的人。
- `name` 必须沿用小说中的原名；只有确实没有名字但剧情需要后续生成时，才可以用玄幻语境下的身份称谓命名，例如“守山弟子”“执法长老”“青衣药童”“黑甲妖兵甲”。
- 无名但有剧情功能的人也要抽取为角色。只要此人有独立动作、对白、施法、阻拦、通报、引路、救治、追杀、盘问、交付信物、启动阵法等剧情功能，就用稳定身份称谓命名。
- 一个条目只能代表一个具体人物，不能把“众弟子”“群妖”“仙门众人”“魔兵们”“围观修士”这类群体当成角色；如果群体里有单独行动的人，应拆成具体人物或身份称谓。
- 无名功能角色命名要使用“限定词 + 身份”，保持玄幻/古风语境。好例子：`山门守卫`、`戒律堂执事`、`青衣药童`、`白发丹师`、`黑甲妖兵甲`、`妖市摊主`、`传令剑侍`。坏例子：`路人`、`众人`、`弟子们`、`魔兵们`、`一个人`、`某修士`。
- `episode_keys` 是必填字段，必须是非空数组；数组值只能从“全集 episode_key 列表”逐字复制，例如 `episode_001`。
- 判断 `episode_keys` 时只依据“完整小说正文”这个 JSON 的外层 episode key；角色出现在哪个 episode 的正文里，就填写哪个 episode key。
- 如果无法从完整小说正文中确定某个角色对应的 episode_key，不要输出这个角色；不要输出空数组、`null`、中文章节名或自造 key。
- 如果角色跨多集出现，按输入 episode_key 顺序列出所有实际出现或被明确提到并影响剧情的集。
- `source_chapters` 填写该角色出现的源章节范围或章节号，例如“第1章”“第3章-第5章”。如果正文只有分集没有源章节，则从该集开头的“源章节”信息推断；仍无法判断时填空数组。
- `brief` 用一句话说明年龄感、身份、剧情功能，不要剧透后期反转。
- `aliases` 写小说中的别称、称呼、身份名；不要自造无依据别名。
- `appearance_notes` 只记录正文已经明确给出的稳定外观线索，例如年龄感、性别呈现、身形、发型、服装气质、标志物；没有就填空数组。
- `has_dialogue` 表示此角色是否有明确对白、喊话、传音或命令。
- `visual_reuse_required` 表示后续镜头是否需要复用稳定外观；主要角色通常为 `true`，功能角色按实际镜头需要判断。
- 不要输出 `importance` 字段，不要使用 `lead/main/supporting/minor/background` 五级分类。
- 输出前自检：每个 `roles[]` 条目都必须有非空 `name`、合法 `role_tier`、非空 `episode_keys`，且 `episode_keys` 全部属于全集 episode_key 列表；不满足就删除该条目。
- 不要输出剧情梗概、分镜、道具清单或场景清单。
- 输出必须符合调用方提供的 JSON schema。
