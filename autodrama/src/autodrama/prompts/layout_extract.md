# 任务

根据全剧完整正文，维护后续长剧集镜头生成会用到的场景介绍表 `generated_layout_intro`。

这个节点只做场景提取与补充，不写生图 prompt，不写画幅、镜头参数、模型名称或图片生成建议。

# 输入

全剧完整正文 novel_full_all_episodes：
{{novel_full_all_episodes}}

已有场景介绍 generated_layout_intro：
{{generated_layout_intro}}

# 输出字段

- `generated_layout_intro`：对象，键为场景名，值为一句话介绍。
- `notes`：可选，简短说明本轮新增、保留或调整的依据。

# 要求

- 输出必须是完整的 `generated_layout_intro`，不是只输出新增项；已有合理场景要保留。
- 场景提取服务于后续镜头和视频生成参考图。只有故事真实发生、角色行动、对话、对峙、追逐、探索、仪式、战斗或关键情节推进所在的空间才需要提取。
- 如果某个地点只是角色提及、回忆中一带而过、背景设定里出现，但当前故事没有把镜头实际放在那里，不要提取。
- 合并本质相同的地点，不要因为一次镜头角度、短暂人物动作、临时道具摆放或称呼差异拆成多个场景。
- 场景名使用短名称，例如「小燕家大厅」「医院走廊」「后山祭坛」。不要写项目 ID、文件名、节点名或技术字段。
- 场景一句话介绍只写空间功能和可见稳定特征，说明它为什么会成为镜头参考图；不要写完整生图 prompt。
- 如果是同一个场景的明显不同视觉状态，并且这个状态会影响后续镜头参考图，应使用 `场景名_状态` 作为键，例如「小燕家大厅_黑夜」「医院走廊_停电后」。
- 状态场景的值只写“相比原场景发生了哪些变化”，例如光线、天气、破损、陈设移动、污染、火灾后、仪式后、战斗后；不要重复原场景完整介绍。
- 如果只有一句台词提到“白天/黑夜/雨天”，但镜头没有真正发生在该状态，不要创建状态场景。
- 不要输出人物、道具、服装、车辆特写、纯天气、纯情绪氛围或没有明确空间锚点的概念。
- 输出必须符合调用方提供的 JSON schema。
